# Процесс работы над Jackdaw с Cursor (агент)

Документ описывает, как мы с агентом в Cursor обычно делаем задачи: от багрепорта до пуша в `main`. Составлен по реальной сессии августа 2026 (почта, compose, избранные, вложения, тема, иконки).

---

## 1. Роли

| Кто | Что делает |
|-----|------------|
| **Вы** | Описываете проблему или фичу, присылаете скриншоты, проверяете сборку вручную, говорите «пушни» / «коммить» |
| **Агент (Cursor)** | Разбирает код, правит min diff, гоняет проверки, собирает `.app`, коммитит и пушит **только по явной просьбе** |

Агент следует правилам из `AGENTS.md`, `.cursor/rules/` и user rules (в т.ч. «не коммитить без запроса»).

---

## 2. Как начинается задача

### Хороший багрепорт

1. **Что ожидали** и **что получили** (одним абзацем).
2. **Скриншот** — особенно для UI (избранные, compose, фильтры).
3. **Шаги воспроизведения**, например:
   - «Запуск приложения → сразу открываю Почту → избранные серые»
   - «Переключаюсь на Календарь → обратно на Почту → тогда работает»
4. **Ограничения**, если важны: «super sync общего ящика ~3 с не трогать», «OWA / shared mailbox integrators».

### Как агент уточняет контекст

- Читает затронутые файлы и соседний код.
- Ищет по репозиторию (`grep`, структура `app/`, `desktop/`).
- При необходимости смотрит **транскрипт прошлого чата** (`agent-transcripts/`), чтобы не потерять контекст между сессиями.
- Для desktop/OTA перед изменениями релиза — **обязательно** `docs/systems/desktop-build/ota-jackdaw.md`.

## 3. Разработка и отладка

### Принципы правок

- **Min diff** — только то, что нужно для задачи; без массового форматирования и «красоты ради красоты».
- **Не ломать контракты** API, super sync, polling, уведомления — если задача этого не требует.
- **Корень проблемы**, а не симптом (например, не «перерисовать при смене вкладки», а «подписаться на загрузку дерева папок»).
- Комментарии и отчёты агента — **на русском**, если вы не просили иное.

### Типичный цикл отладки

```
Багрепорт → гипотеза → чтение кода → правка → автопроверки → локальная сборка → вы проверяете → доработка → (по запросу) commit + push
```

### Команды (через `rtk`)

Все команды разработки идут через **`rtk`**, не напрямую:

```bash
# Статус и diff
rtk git status
rtk git diff

# Typecheck (Svelte/TS)
cd app && rtk npm run check

# Тесты (пример)
cd app && rtk npm run test -- --run test/frontend/Mail/composeQuote.test.ts

# Локализация после новых строк
cd app && rtk npm run l10n:extract
```

### Локальный запуск desktop

На этой машине **`npm run dev` для Electron часто не работает** (ESM + Electron 41). Для ручной проверки агент собирает unpacked `.app`:

```bash
cd desktop && npm run build && npx electron-builder --mac --dir
# Результат: desktop/dist/mac-universal/Jackdaw.app (или mac-arm64)
open desktop/dist/mac-universal/Jackdaw.app
```

Вы проверяете **именно эту сборку**, а не старый установленный Jackdaw из `/Applications`, если агент явно не сказал иное.

### Что агент проверяет сам

После правок:

- [ ] lint / typecheck по затронутым файлам
- [ ] unit-тесты, если есть или добавлены по делу
- [ ] нет `console.log`, TODO, секретов в diff
- [ ] регресс соседних сценариев (мысленно + по коду)

### Что проверяете вы

- Холодный старт приложения (важно для избранных, login, sync).
- Реальный OWA / shared mailbox, не только mock.
- Compose: ответ, цитата, картинки, отправка.
- Фильтры («С вложениями», «С флажком»).
- Переключение вкладок (Почта ↔ Календарь) — регресс после фиксов реактивности.

Фразы вроде **«да, работает»**, **«неа, всё ещё серое»** — сигнал для следующей итерации.

## 4. Примеры из нашей сессии (как отлаживали)

### Избранные папки не активны при старте

| Этап | Действие |
|------|----------|
| Симптом | Серые placeholder «Входящие»; после Calendar → Mail всё ок |
| Гипотеза | Svelte не пересчитывает `findFavoriteFolder` после async `listFolders()` |
| Промежуточные попытки | `mergeColls(rootFolders)`, реактивность `$favoriteFoldersSetting`, placeholder из localStorage |
| Итог | `watchMailFolderTrees()` + `favoriteFoldersEpoch` + `startFavoriteFolderTracking()` в `MailInBackground.svelte` (как `mailUnreadCounts`) |

### Compose / цитата при ответе

| Этап | Действие |
|------|----------|
| Симптом | TipTap ломает HTML цитаты (шрифты, отступы, картинки) |
| Решение | Гибрид: TipTap только для редактируемой части + `ComposeQuoteEditor` (contenteditable) для цитаты |
| Сборка письма | `mergeComposeQuote()` / `splitComposeQuote()` в `composeQuote.ts` |

### Фильтр «С вложениями» только за сегодня

| Этап | Действие |
|------|----------|
| Причина | Backfill GetItem только для ~100 новых писем; в list headers не было `HasAttachments` |
| Решение | `HasAttachments` в FindItem, флаг в `EMail`, фоновый `syncHasAttachmentFlags()` без блокировки hot sync |

### Super sync shared mailbox при старте (~3 с)

- Это **задумано**: `startupDependentAccounts()` в `OWAAccount.ts`.
- Агент **не убирал** этот путь без вашего явного решения.

## 6. Коммит и push

### Когда пушим

- **Только когда вы явно просите**: «пушни», «закоммить», «обновлю себе прогу».
- Если неясно — агент **спрашивает**, а не коммитит сам.

### Как агент готовит коммит

1. Параллельно:
   - `rtk git status`
   - `rtk git diff` (staged + unstaged)
   - `rtk git log -5 --oneline` (стиль сообщений)
2. Исключает секреты (`.env`, токены) и артеfact’ы сборки.
3. Пишет сообщение **1–2 предложения, фокус на «зачем»**, на русском (как в прошлых коммитах).
4. `rtk git add …` → `rtk git commit` (HEREDOC) → `rtk git push`.
5. Показывает хеш коммита и краткий список «что внутри».

### Запрещено агентом (git safety)

- `git push --force` на main
- `--no-verify`, amend без условий из user rules
- менять `git config`

### После push — как вам обновиться

1. **OTA (GitHub Releases)** — дождаться CI `publish-desktop-jackdaw.yml`, если пользуетесь автообновлением.
2. **Локально** — `git pull` + сборка:
   ```bash
   cd desktop && npm run build && npx electron-builder --mac --dir
   ```
3. Открыть свежий `Jackdaw.app` из `desktop/dist/…`.

Документация OTA: `docs/systems/desktop-build/ota-jackdaw.md`, установка: `docs/INSTALL.md`.

## 7. Чеклист «готово к пушу»

Перед вашим «пушни» имеет смысл пройтись:

- [ ] Вы подтвердили сценарий на **свежей сборке**
- [ ] Холодный старт / shared mailbox / compose — по затронутым областям
- [ ] `rtk npm run check` без новых ошибок в наших файлах
- [ ] Тесты по новой логике зелёные (если добавлялись)
- [ ] В diff нет `tsbuildinfo`, секретов, случайного форматирования
- [ ] Super sync и уведомления не сломаны намеренно

## 8. Шаблон сообщения агенту

**Новая фича:**
> Нужно … (как в Outlook). Не трогать …. Скрин приложил.

**Баг:**
> При … получаю …. Ожидал …. После перезапуска / смены вкладки …. Скрин.

**Готово к релизу:**
> Всё ок, пушни в main.

**Только локально:**
> Пока не пушь, хочу ещё потестить.
